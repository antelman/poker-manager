# 🃏 ניהול משחק פוקר

אפליקציית ווב לניהול ערב פוקר בין חברים: מי נכנס, כמה פעמים, כמה ז'יטונים נשארו לכל אחד
בסוף הערב — ומי בסוף משלם למי, בכמה שפחות העברות כסף.

בנויה מובייל-ראשון, בעברית, עובדת גם בלי אינטרנט, ואפשר להתקין אותה על המסך הראשי של הטלפון.

---

## מה היא עושה

**במהלך המשחק**
- הגדרת עלות כניסה, מטבע (₪ / $ / €) וכמה ז'יטונים מקבלים על כניסה
- הוספת שחקנים בלחיצה, עם חיוב כניסה אוטומטי
- כפתורי **+** / **−** לכל שחקן לריביי (כניסה נוספת) ולביטול טעות
- הקופה מתעדכנת בזמן אמת בראש המסך

**בסוף המשחק**
- כל שחקן מזין כמה ז'יטונים נשארו לו, והאפליקציה ממירה לכסף
- אפשר גם לעבוד ישירות בכסף במקום בז'יטונים (בהגדרות)
- כפתור **"מה שנשאר"** ממלא אוטומטית לשחקן האחרון את היתרה
- זיהוי אוטומטי אם הספירה לא מסתדרת עם הקופה, עם אפשרות לחלק את ההפרש
  שווה בשווה או לפי גודל הערימה

**החשבון**
- טבלת תוצאות מדורגת: כמה כל אחד הכניס, הוציא, ומה השורה התחתונה
- רשימת תשלומים מינימלית — מי משלם למי וכמה
- צ'קבוקס לסימון תשלום שבוצע
- שיתוף הסיכום בוואטסאפ או העתקה ללוח

**אחרי**
- היסטוריית משחקים נשמרת במכשיר
- ייצוא כל הנתונים כקובץ JSON

## איך מריצים

```bash
npm start          # http://localhost:8080
npm test           # בדיקות של מנוע החישוב
```

אין תלויות ואין שלב build — אלה קבצים סטטיים שרצים כמו שהם.


### על החישוב

כל הכסף מנוהל כמספרים שלמים באגורות, כך שספירת ז'יטונים לא נסחפת בשגיאות עיגול
של נקודה צפה. חלוקת התשלומים משתמשת בהתאמה חמדנית בין החייב הגדול לזוכה הגדול,
שמסלקת את השולחן בלא יותר מ‑n−1 העברות — מה שחשוב כשאנשים באמת מעבירים מזומן
מיד ליד סביב השולחן.

אם הספירה לא מסתדרת עם הקופה, האפליקציה **לא** מבליעה את ההפרש בשקט אצל שחקן
אקראי אלא מציגה אותו ומציעה לחלק אותו במפורש.

## סריקת קלפים במצלמה

בתוך מסך **הסיבוב**, מתחת ללוח, יש כפתור **"סרוק קלפים במצלמה"**. הוא פותח את
המצלמה של הטלפון, מזהה את הקלפים שעל השולחן, ומציע אותם להוספה ללוח בהקשה אחת.

- **הכול קורה במכשיר** — אין שרת, אין מודל להוריד, ואף תמונה לא נשמרת ולא נשלחת
  לשום מקום. גם אופליין.
- **אפשר לצלם מהצד** — האפליקציה מוצאת את ארבע הפינות של כל קלף ומיישרת אותו,
  כך שהטלפון לא חייב להיות בדיוק מעל השולחן. גם קלף מסובב או הפוך נקרא.
- **כלום לא נכנס ללוח לבד** — הקלפים מוצעים, הקשה על קלף מסירה אותו מהרשימה,
  וכפתור אחד מוסיף את מה שנשאר. אם הזיהוי לא בטוח מספיק הוא מסמן את הקלף
  ולא נותן לו שם, במקום לנחש.

## מצב שולחן — המצלמה מנהלת את הסיבובים

במסך **הסיבוב** יש כפתור **"מצב שולחן — מצלמה פתוחה כל הערב"**. מניחים את הטלפון
כך שיראה את אזור הקלפים המשותפים, ממזערים, וממשיכים לשחק. מכאן המצלמה עושה את
העבודה:

| מה קורה על השולחן | מה האפליקציה עושה |
| --- | --- |
| קלפים יורדים ונשארים כשנייה | פותחת סיבוב חדש ומעלה בליינדים |
| פלופ / טרן / ריבר נפתחים | מוסיפה אותם ללוח ומקדמת את השלב |
| השולחן מתפנה | ספירה לאחור קצרה, ואז סוגרת את היד |
| היד נסגרה | שואלת את השאלה היחידה שמצלמה לא יכולה לדעת: **מי לקח את הקופה** |
| קלפים חדשים יורדים | סיבוב הבא נפתח לבד, וחוזר חלילה |

**מה היא לא עושה לבד:** היא לא מחליטה מי ניצח ולא נוגעת בכסף. הקופה מחולקת רק
אחרי שמישהו סימן את המנצח, בדיוק כמו קודם.

**כשמושכים יד מעל השולחן** הקלפים נעלמים לרגע — לכן פתיחת סיבוב דורשת שהקלפים
יישארו כשנייה, וסגירה דורשת שהשולחן יישאר ריק כמה שניות, עם ספירה לאחור שמתבטלת
ברגע שקלף חוזר לתמונה.

**קלף שנוסף בטעות** — יש כפתור "בטל" ליד ההודעה בלוח המחוונים של המצלמה, ותמיד
אפשר להקיש על משבצת בלוח ולתקן ידנית.

**סוללה** — מצלמה פתוחה כל הערב לא יכולה לעבד עשר תמונות בשנייה. כל פריים נבדק
קודם מול תמונונת 96×64 של הקודם, והעיבוד הכבד רץ רק כשמשהו זז. נמדד בפועל:
**קריאה מלאה אחת בשנייה בשולחן דומם, מול 8.7 בשולחן פעיל.** בנוסף המסך ננעל
פתוח (Wake Lock) כל עוד מצב שולחן דולק, ומעבר לאפליקציה אחרת רק מקפיא את העיבוד
— בחזרה הוא ממשיך מאיפה שהפסיק.

**מגבלה שכדאי להכיר:** "השולחן התפנה" נמדד לפי היעדר מלבנים בצורת קלף בתמונה.
אם חפיסה או קלפים שנאספו נשארים בפריים, הם ייחשבו כשולחן תפוס — לכן כדאי לכוון
את הטלפון לאזור הקלפים המשותפים בלבד.

### לימוד החפיסה (מומלץ, פעם אחת)

מהמסך של הסריקה: **"למד את החפיסה"**. האפליקציה מבקשת 13 ערכים וארבע סדרות,
מחזיקים קלף מול המצלמה ומצלמים. התבניות נשמרות במכשיר, וזה מה שהופך את הזיהוי
מ"טוב ברוב הפעמים" ל"עקבי" — כי כל חפיסה מדפיסה את הפינה קצת אחרת.

בלי הלימוד הסריקה עובדת על תבניות מובנות, וזה מספיק לחפיסה סטנדרטית באור סביר.

### מה עוזר ומה מפריע

| עוזר | מפריע |
| --- | --- |
| אור אחיד מלמעלה | צל חד או ברק מהפלאש על הקלף |
| קלפים מופרדים זה מזה | קלף שמכסה חלקית קלף אחר |
| כל הקלף בתוך הפריים | פינה שיוצאת מהמסך |
| טלפון יציב לרגע | תנועה מהירה שמטשטשת את הפריים |

הזיהוי דורש שכל ארבע הפינות של הקלף ייראו, והוא מדווח קלף רק אחרי שהוא קרא אותו
אותו דבר בכמה פריימים ברצף. אפשר תמיד להקליד קלף ידנית בבורר — הסריקה היא קיצור
דרך, לא תנאי.

## מצלמת שולחן במחשב (ניסיוני)

`vision/` הוא כלי Python נפרד שעושה את אותו דבר ממחשב עם מצלמה, ובנוסף סופר
ז'יטונים לפי צבע. הוא לא חלק מהאפליקציה ולא נדרש לה — הדרך הרגילה היא הסריקה
מהטלפון שלמעלה. פרטים: [`vision/README.md`](vision/README.md).
