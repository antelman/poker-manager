# 📷 מצלמת שולחן — קריאה חיה של קלפים וז'יטונים

סקריפט Python שמדליק מצלמה, מזהה בזמן אמת את הקלפים שנפתחו על השולחן, סופר את
הז'יטונים שכל שחקן הימר, ומתרגם אותם לכסף לפי ערך שמוגדר לכל צבע.

> **לסריקת קלפים מהטלפון אין צורך בכלי הזה.** האפליקציה עצמה סורקת קלפים
> במצלמה של הטלפון, בלי התקנה ובלי מחשב — ראו "סריקת קלפים במצלמה"
> ב‑[README הראשי](../README.md). הכלי כאן הוא לשולחן עם מחשב ומצלמה קבועה,
> והיתרון היחיד שלו הוא ספירת הז'יטונים לפי צבע, שעדיין לא קיימת באפליקציה.

הסקריפט עומד בפני עצמו — הוא לא נוגע באפליקציית הווב — אבל הוא מפרסם את המצב
כ‑JSON (לקובץ או ב‑HTTP), כך שאפשר יהיה לחבר אליו את השולחן בהמשך.

## התקנה

```bash
python3 -m pip install -r vision/requirements.txt
```

בדיקה שהכול תקין, בלי מצלמה בכלל:

```bash
python3 vision/table_vision.py selftest
```

## הרצה מהירה

```bash
python3 vision/table_vision.py live --source demo   # שולחן מצויר, בלי חומרה
python3 vision/table_vision.py live                 # המצלמה הראשונה במחשב
```

בחלון הווידאו: `q` יציאה, `r` יד חדשה, `s` שמירת צילום מסך.

## כיול — שלוש פעולות שעושים פעם אחת

### 1. ללמד את החפיסה שלך

```bash
python3 vision/table_vision.py learn-cards
```

הסקריפט מבקש 13 ערכים ו‑4 סדרות, אחד אחרי השני. מחזיקים קלף מול המצלמה, שטוח
ומואר, ולוחצים `SPACE` כשהמסגרת הירוקה יושבת עליו (`s` לדילוג, `q` ליציאה).
התמונות נשמרות ב‑`vision/data/templates/`. בלי השלב הזה הקלפים עדיין מזוהים על
השולחן — פשוט בלי שם.

### 2. להגדיר כמה שווה כל צבע ז'יטון

```bash
python3 vision/table_vision.py calibrate-chips
```

לוחצים עם העכבר על ז'יטון בתמונה, ומקלידים בטרמינל שם וערך (`אדום`, `5`).
הצבע נדגם מהז'יטון האמיתי שלך תחת התאורה שלך, ונשמר ב‑`vision/config.json`.
לחיצה חוזרת על אותו שם מעדכנת אותו.

בלי חלון גרפי (למשל בשרת) אפשר גם:

```bash
python3 vision/table_vision.py calibrate-chips --source photo.jpg --at 420,530 --name אדום --value 5
```

### 3. לסמן איפה יושב כל שחקן

```bash
python3 vision/table_vision.py regions
```

גוררים מלבן סביב אזור ההימור של כל שחקן ומקלידים שם וסוג:
`player` (שחקן), `board` (הקלפים המשותפים) או `pot` (הקופה).
`c` מנקה הכול. ז'יטונים שלא נופלים באף אזור נספרים בנפרד תחת "שאר השולחן".

גם כאן יש דרך בלי עכבר (הקואורדינטות יחסיות, 0..1):

```bash
python3 vision/table_vision.py regions \
  --add "board:board:0.15,0.05,0.7,0.45" \
  --add "דני:player:0.02,0.7,0.3,0.28"
```

`vision/config.example.json` הוא דוגמה מלאה לקובץ שנוצר.

## פלט

כל שינוי מודפס לטרמינל:

```
[22:14:07] קלפים: A♠ K♥ 7♦ | הימורים: דני: 10₪  יוסי: 35₪ | סה"כ 45₪
```

ואפשר גם לפרסם אותו החוצה:

```bash
python3 vision/table_vision.py live --json-out vision/data/state.json   # קובץ
python3 vision/table_vision.py live --serve 8765                        # HTTP
```

```json
{
  "ts": 1788083680.282,
  "frame": 64,
  "unit": "₪",
  "cards": [{ "label": "As", "rank": "A", "suit": "s", "pretty": "A♠", "score": 1.0,
              "box": [119, 115, 130, 195], "region": "board" }],
  "board": ["As", "Kh", "7d"],
  "revealed": ["As", "Kh", "7d"],
  "chips": {
    "regions": [{ "name": "דני", "kind": "player", "counts": { "אדום": 2 },
                  "valueCents": 1000, "chips": 2 }],
    "totalCents": 4500, "total": "45", "unknown": 0
  }
}
```

כסף נשמר באגורות שלמות (`valueCents`), בדיוק כמו ב‑`src/engine.js`, כדי שספירת
ז'יטונים לא תיסחף בשגיאות עיגול.

השרת פתוח ל‑CORS, כך שדף מקומי יכול פשוט למשוך אותו:

```js
const state = await fetch('http://localhost:8765/state').then((r) => r.json());
```

## הפקודות

| פקודה | מה היא עושה |
| --- | --- |
| `live` | קריאה חיה מהמצלמה |
| `learn-cards` | לימוד הערכים והסדרות מהחפיסה שלך |
| `calibrate-chips` | צבע ז'יטון → ערך כספי |
| `regions` | סימון אזורי ההימור |
| `selftest` | בדיקה מקצה לקצה בלי מצלמה |

דגלים שימושיים ל‑`live`: `--source` (מספר מצלמה / קובץ / `demo`), `--no-window`,
`--quiet`, `--fps 15`, `--max-frames`, `--width 1280`, `--config`, `--templates`.

## איך זה עובד

**קלפים** — הפריים עובר לגווני אפור וסף בהירות מעל רמת הלבד, כך שהקלפים הבהירים
בולטים. כל קונטור עם ארבע פינות ויחס צלעות של קלף מיושר לתמונה של 200×300, ומהפינה
השמאלית העליונה נחתכים הערך והסדרה ומושווים לתבניות שנלמדו. קלף מדווח רק אחרי
שהוא נקרא אותו דבר בכמה פריימים ברצף, כדי שיד שעוברת מעל השולחן לא תמציא קלפים.

**ז'יטונים** — טרנספורם האף למעגלים מוצא את הז'יטונים; הצבע נדגם ממרכז הז'יטון
ומושווה לצבעים המכוילים במרחק HSV (גוון מחושב במעגל, וגוון נעלם בז'יטונים לבנים
ושחורים שבהם הוא רעש בלבד). מעגלים בתוך קלפים או כאלה שאינם צבע אחיד נזרקים, כדי
שסמלים על הקלפים לא ייספרו ככסף.

## מגבלות שכדאי להכיר

- **ערימות** — מלמעלה רואים רק את הז'יטון העליון, ולכן ערימה נספרת כז'יטון אחד.
  פורסים את ההימור בשורה מול השחקן, או מכוונים מצלמה שנייה מהצד.
- **תאורה** — צל חזק או ברק על הקלף פוגעים בזיהוי יותר מכל דבר אחר. אור אחיד
  מלמעלה, בלי פלאש, עובד הכי טוב.
- **חפיפה** — קלף שמכסה חלקית קלף אחר לא ייקרא; הקלפים צריכים להיות מופרדים.
- **זווית** — המצלמה צריכה להיות מעל השולחן. זווית קיצונית מעוותת את הפינה שממנה
  נקרא הערך.
- זהו כלי עזר לשולחן ביתי, לא שופט. תמיד אפשר לתקן ידנית באפליקציה.

## פתרון בעיות

| תסמין | מה לעשות |
| --- | --- |
| `לא הצלחתי לפתוח מצלמה 0` | לבדוק הרשאת מצלמה, לנסות `--source 1`, או `--source demo` |
| קלפים לא מזוהים בכלל | להוריד את `cards.thresholdOffset` בקונפיג (לבד בהיר), או להאיר את השולחן |
| מזוהים "קלפים" שהם לא קלפים | להעלות את `cards.minAreaFrac` |
| הערך נקרא לא נכון | להריץ `learn-cards` מחדש באותה תאורה, או להעלות את `cards.matchMaxDiff` |
| ז'יטונים לא נספרים | לכוונן `chips.minRadiusFrac` / `maxRadiusFrac` לגודל בפריים, ואז את `param2` |
| צבע יוצא "לא מזוהה" | לכייל אותו מחדש, או להעלות `maxDistance` לאותו צבע |
